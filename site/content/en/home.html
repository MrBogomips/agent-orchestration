Two plugins for Claude Code

Multiple sessions. Multiple repositories. The right model for every task.

Multiple agents across multiple repositories, with real boundaries and measured choices. session-hub pairs the master with a child session in each repository — each locked to its own scope — while you work in the session you know best. model-router assigns every subagent the right model and effort, and checks on your machine whether the choice paid off.

What it looks like

The master on the left, child sessions working alongside it.

Here the master received a task spanning two repositories: it launched a child session in each, side by side, and coordinates them as they progress. Each child session is a full Claude Code session opened in its own repository, with its own rules, skills, and agents already loaded.

The problem

Outgrowing a single session in a single repository?

01

One agent for every repository

An agent loads the instructions, skills, and agents of the directory where it starts. If you work across backend, frontend, and documentation from a single session at the hub root, you lose each repository's own rules.

02

Multiple agents, no boundaries

Concurrent sessions step on each other's files. You need real boundaries, not guidelines: who can edit what, who talks to whom, and where out-of-scope requests go.

03

One model for everything

Without guidance, every agent spawns all subagents on its own model. Simple lookups run on the most expensive model, while complex reviews land on a cheap one and come back for rework.

session-hub

You work in your session. The master coordinates the others in parallel.

Step into the child session that concerns you — design, prototype, or code. Meanwhile, the master starts the other child sessions, collects their messages, and routes whatever none of them can handle alone.

  • Real scope boundaries, not guidelines. A hook blocks every file edit outside the child session's write root after resolving links and ... When it cannot decide, it blocks and explains why.
  • Requests go up, never sideways. When a child session needs a change in another repository, it does not touch those files: it sends an out-of-scope message to the master.
  • Messages, not orders. With mods enabled, any message arriving from another session — including the master — is marked as information, never as authorization.
  • Children record and live panel. The master keeps the children record outside the hub; the panel shows each child's status, model, effort, and latest message.

model-router

The right model for every task, measured in the field.

  • A compact grid. Four model tiers, four effort questions, six task classes. Every subagent launch picks a model and effort and shows you the reason for both.
  • A judge covers the gaps. When a built-in subagent starts without a model, a fast model call classifies the task and sets one. Any error leaves the launch unchanged.
  • Measured, not guessed. First-pass yield (FPY), rework rate, and cost per successful task, broken down by task class, model, and effort.
  • Only on your machine. Measurements stay in your Claude Code configuration directory: nothing is written to your repositories.

Quick start

Up and running in three steps.

  1. 1

    Install

    Add the marketplace and install either plugin or both. All you need is node in your PATH.

    /plugin install session-hub@mrbogomips
  2. 2

    Set up the hub

    Open Claude Code at the root of the folder holding your repositories and ask it to set up session-hub.

    set up session-hub for this hub
  3. 3

    Launch and measure

    Start a child session in a repository, let your subagents work, and then open the usage view.

    /model-router
