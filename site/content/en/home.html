Two plugins for Claude Code

Multiple sessions. Multiple repositories. The right model for every task.

Work in parallel across multiple repositories without file conflicts or wasted tokens. session-hub pairs a master session with a dedicated child session for each repository — each isolated within its own scope — while you step into whichever session fits your role best. model-router assigns the right model and effort to every delegated task and measures on your machine whether that choice paid off on the first try.

The problem

Outgrowing a single session in a single repository?

01

One agent across all repositories

An agent loads instructions, skills, and definitions from the directory where it starts. If you work across backend, frontend, and docs from a single session at the hub root, you lose each repository's own rules.

02

Multiple agents, no boundaries

Concurrent sessions end up stepping on each other's toes over the same files. You need hard technical boundaries, not polite prompt reminders: who can write where, who can talk to whom, and how out-of-scope requests are handled.

03

One model for everything

Without a shared policy, every agent spawns all subagents on its own model. Trivial lookups burn tokens on the most expensive model, while tricky reviews land on a lightweight one and come back needing rework.

session-hub

You work in your session. The master coordinates the rest in parallel.

Jump straight into the session you care about — design, prototype, or code — while the master launches the other child sessions, gathers their updates, and routes anything no single session can handle alone.

  • Hard write boundaries, not suggestions. A hook blocks any file edit outside a child session's write root after resolving symlinks and .. segments. It fails closed and explains why.
  • Requests go up, never sideways. When a child session needs a change in another repository, it doesn't touch those files — it sends an out-of-scope request up to the master.
  • Messages, never permissions. With mods enabled, any message coming from another session — including the master — is tagged strictly as information, never as an implicit command or authorization.
  • Live record and panel. The master keeps the child session record outside the hub, while the live panel shows each child session's status, model, effort, and latest message.

model-router

The right model for every task, measured in the field.

Stop guessing models and effort levels. A clear routing grid decides before every launch, and local tracking shows what it actually costs to get a working result on the first try.

  • A lean routing grid. Four model tiers, four effort questions, six task classes. On every launch, the agent states the model, effort, and reasoning behind the choice.
  • A judge fills the gaps. When a built-in subagent starts without a model specified, a fast classifier evaluates the task and sets model and effort on the fly. It fails open, leaving the launch unchanged if an error occurs.
  • Measured, not estimated. First-pass yield (FPY), rework rate, and cost per success, broken down by task class, model, and effort.
  • Strictly on your machine. All data stays local inside your Claude Code config directory — nothing is ever written to your repositories.

Architecture

Two plugins, one contract.

You can install and run either plugin completely on its own. When used together, session-hub delegates model and effort selection for every child session to model-router, without duplicating rules or cluttering your repositories.

Quickstart

Up and running in three steps.

  1. 1

    Install

    Add the marketplace and install either plugin or both. All you need is node in your PATH.

    /plugin install session-hub@mrbogomips
  2. 2

    Configure the hub

    Open Claude Code at the root of the directory holding your repositories and ask it to set up session-hub.

    set up session-hub for this hub
  3. 3

    Launch and measure

    Start a child session in a repository, let the subagents do their work, and open the usage view.

    /model-router
