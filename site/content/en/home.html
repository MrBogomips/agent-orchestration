Two plugins for Claude Code

Many sessions. Many repositories. The right model for each task.

session-hub lets one master session run a child session in each repository, in parallel, each held to its own scope, while you work in the session you know best. model-router gives every subagent the model and the effort its task needs, and measures on your machine whether the choice worked.

What it looks like

One master on the left, the children working beside it.

The master session was asked for a task that touches two repositories. It started one child in each, side by side, and keeps coordinating while they work. Each child is a full Claude Code session, opened in its own repository with that repository's rules, skills and agents loaded.

The problem

Outgrown one session in one repository?

01

One agent, every repository

An agent loads the instructions, skills and agents of the folder it runs in. A single session working across the backend, the frontend and the docs from the hub's root misses each repository's own rules.

02

Agents side by side

Several sessions working at once step on each other's files unless something says what each one may change, whom it talks to and where a request outside its task goes.

03

One model for everything

Left to itself, an agent starts every subagent on its own model. Simple searches run on the most expensive model, and hard reviews sometimes run on a cheap one and come back for rework.

session-hub

Work in your session. The master runs the others in parallel.

You type into the child whose work you know, the design, the prototype or the code. The master starts the other children, hears their messages and routes what each one cannot do itself.

  • Children with a real scope. A hook blocks file edits outside the child's write root, after resolving links and ... When it cannot decide, it blocks and says why.
  • Requests go up, not sideways. A child that needs a change in another repository sends an out-of-scope message to the master instead of editing it.
  • Messages are not orders. With mods on, a message from another session, the master's included, is marked as information, not authorization.
  • A record and a live panel. The master keeps a record of every child outside the hub; the panel shows each child's status, model, effort and last message.

model-router

The right model for each task, and a measure of how well it worked.

  • One short grid. Four model tiers, four effort questions, six task classes. Every subagent start carries a model and an effort, and you see why each was chosen.
  • A judge fills the gaps. When a built-in subagent start still carries no model, one call to a fast model classifies the task and sets one. Any error leaves the start unchanged.
  • Measured, not guessed. First-pass yield, rework rate and cost per successful task, per task class, model and effort.
  • On your machine. The measurements stay under your Claude Code config folder; nothing is written inside your repositories.

Quickstart

Up and running in three steps.

  1. 1

    Install

    Add the marketplace and install one plugin or both. You need node on your PATH.

    /plugin install session-hub@mrbogomips
  2. 2

    Set up the hub

    Open Claude Code at the root of a folder of repositories and ask to set up session-hub.

    set up session-hub for this hub
  3. 3

    Spawn and measure

    Ask for a child in a repository, let subagents run, then open the usage view.

    /model-router
